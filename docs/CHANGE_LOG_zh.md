## [未发布] (Unreleased)

### 新增
- 新增**葡萄柚树**以及挂在树下的果实：
  - `aliment:grapefruit_log`、`aliment:grapefruit_leaves`、`aliment:grapefruit_sapling` 是一棵独立的柑橘树。它生成于丛林与热带草原，每 6 个区块尝试一次，树苗会长出同样的树。
  - `aliment:grapefruit` 是果实，而且是**悬挂**的：由原版的 `minecraft:attached_to_leaves` 装饰器放置在树冠叶片正下方，并且只有上方仍是树叶或原木时才能存在，因此破坏树冠会把它打落。
  - 一个葡萄柚可合成 **8 个** `aliment:grapefruit_slice`，这才是玩家吃的部分：**2 饱食度**、**3 饱和度**、**5 水量**、**1 香柠檬素**、**10 维生素 C**——维生素 C 与胡萝卜相同，因为果片既是植物性食物又是柑橘。它是本模组唯一既能吃又能补水的食物，也是少数**饱腹时仍可食用**的食物之一，因为玩家吃它是为了香柠檬素而不是为了饱食度。
- 新增**葡萄柚木材全套**，成为继柳木之后第二套完整木材：`grapefruit_wood`、`stripped_grapefruit_log`、`stripped_grapefruit_wood`、木板、楼梯、台阶、栅栏、栅栏门、门、活板门、压力板、按钮、架子、告示牌与悬挂告示牌、树苗盆栽，以及它自己的**船与运输船**——两者各自拥有独立的实体类型、模型层与贴图，这是当前版本每种木材的船所必需的。它自己的 `aliment:grapefruit_logs` 标签是其配方的材料来源，因此木板配方无法用柳木原木满足；同时它加入了原版的 `planks`、`logs`、`wooden_*`、`signs`、`fence_gates` 标签，这正是整套木材能够像其他木材一样用斧开采、并能被原版配方识别的原因。
- 新增**香柠檬素**与 **CYP3A4** 指标：
  - 香柠檬素是葡萄柚携带的成分，范围 0~**10**（十个果片），一个游戏日内清除完毕。它本身没有任何效果，一切都通过酶来体现。
  - CYP3A4 范围 0~**100**，在从未吃过葡萄柚的身体中为 **85**。香柠檬素对它是一个**阶梯函数**而非曲线，因此该指标只会有五个取值之一：2 及以下为 **85**，超过 2 为 **60**，超过 4 为 **45**，超过 7 为 **25**，8.5 及以上为 **10**。
- 牛奶现在被视为饮品，喝一桶可增加标准的 **15 水量**。26.3 中原版牛奶是携带 `CONSUMABLE` 组件的普通 `Item`，而不再是旧版本的 `MilkBucketItem`，正是这一点让本模组的 `Item.finishUsingItem` 钩子能够捕获它。
- 新增**葡萄柚汁**：`minecraft:sugar` + 一个 `aliment:grapefruit_slice` + 一个**水瓶**可合成一个 `aliment:grapefruit_juice`，也就是把果片压进了瓶子里。它是饮品而非食物，因此**饱食度为 0**、且始终可饮；水量取标准饮品的 **15**，而果片只给 5。它原样保留果片的 **1 香柠檬素**与 **10 维生素 C**，并因糖而额外提供 **0.7 葡萄糖**——按面包的档位计，而不是按它所压榨的植物性食物计，因为糖是快吸收碳水。十杯仍是香柠檬素上限，与十个果片完全一样。
  - 其材料不是 `minecraft:potion`，而是一个要求 `minecraft:potion_contents` 为 `minecraft:water` 的 `fabric:components` 过滤器，因此该配方不会接受任意酿造药水。原版的 `Ingredient` 是 `HolderSet<Item>`，无法表达这一条件；而过滤器一旦解析失败，配方会被**静默丢弃**，所以自测既按名字向配方管理器索取该配方，也断言水瓶能匹配、粗制药水不能匹配。
  - 其贴图按**原版药水样式**绘制，也就是本模组其它药水已经在用的惯例：原版的 `potion.png` 瓶身加上 `potion_overlay.png` 液体，把灰阶液体染成果肉色，于是这瓶东西看上去就是葡萄柚。瓶身与原版逐像素一致，属于我们自己的只有染色。
- 新增**葡萄藤**与**葡萄酒**，为发酵罐添上第二种酒：
  - `aliment:grape_vine` 是一种四阶段作物，遵循原版「植物能长在什么上面」的规则：**泥土、草方块、砂土、灰化土*以及耕地***——它按 `minecraft:supports_vegetation` 标签判定，而这个标签本来就把 `minecraft:farmland` 包含在内，所以种子既能种在草地上，也能种在耕地上。它靠骨粉或随机刻推进生长阶段。只有 `age=3` 才结果：掉落 **1~3** 个 `aliment:grape`，而在此之前每个阶段都不掉落任何东西，所以提前采收只是白白浪费一颗种子。它野生生长于平原与温带森林，这也是获得第一串葡萄的唯一途径，因为种子来自果实。
  - 成熟的葡萄藤靠**右键**采收，而不是靠破坏：一采掉落 **1~3** 个葡萄，并把藤退回 **`age=1`**，即比成熟差一个阶段，所以植株不会死、还能再结果。这正是原版甜浆果丛的形状，也是本模组已有的五种植物（黄柏、麻黄、黄连、甘草、海藻）一直在用的做法。`age=3` 之前右键什么也拿不到，而且该次点击会**原样传递**而不是被吞掉，所以骨粉与放种子都还能落在方块上。直接破坏成熟的藤一样给那 1~3 个葡萄——因为葡萄藤本身没有对应物品——所以两种收法唯一的区别就是植株是否留下。
  - 葡萄藤下方的耕地**会保持为耕地**：`aliment:grape_vine` 与小麦、南瓜茎一起被写进 `minecraft:maintains_farmland`，因此种下的葡萄藤属于「能让原版不把脚下的耕地踩回泥土」的作物之一。没有这一条，藤就会长在随时会塌成泥土的地上。
  - `aliment:grape` 是果实：**2 饱食度**、**1.0 饱和度**、随时可食；一个葡萄在合成格里产出两颗 `aliment:grape_seeds`。种子直接种进土里就能长回葡萄藤。
  - `aliment:grape_wine` 是 **5%** 的饮品。它是与 `aliment:wine` **并列的新物品**，而不是对后者的改动：原有的 7% 酒及其 40% 蒸馏流程完全未动，而玩家选择一杯葡萄酒，本来就是有意选这种更淡的酒。
  - 发酵罐用**葡萄 + 糖 + 水 + 酿酒酵母**酿出它。葡萄与糖（**先后顺序随意**）放进去后液体会变成紫色；糖是**补全**葡萄醪而不是替换葡萄，而且**两样都放进去之前酵母会被拒绝**，因为葡萄大部分是水，真正发酵的是糖。45 秒后罐里就是 5% 的葡萄酒，直接装瓶，**不需要蒸馏器**——这一点与啤酒不同，麦醪必须蒸馏。
  - 现在发酵罐的三种配方可以按水里的东西区分：**糖**得 7% 的酒，**小麦**得啤酒，**葡萄 + 糖**得 5% 的葡萄酒。
- 新增**可选的农夫乐事联动**。其配方部分是纯数据层：没有 `fabric.mod.json` 条目、也不引用任何农夫乐事的类。每个联动文件都以 `farmersdelight` 的 `"fabric:all_mods_loaded"` 为条件：
  - 砧板上一把**刀**可把一个 `aliment:grape` 切成三颗 `aliment:grape_seeds`，也可把一个 `aliment:grapefruit` 切成八片。
  - **烹饪锅**可把一个葡萄柚片加糖煮成 `aliment:grapefruit_juice`，并接进你提供的**玻璃瓶**里——用的是它自己煮汤时向你要碗的同一个 `container` 字段，也是没有瓶子就拿不到这杯汁的原因。
  - Aliment 同时发布自己的约定 `c:` 标签——`c:crops/grape`、`c:seeds`、`c:drinks`——这样任何读取约定标签的模组都能找到葡萄、种子与酒。这些标签无论农夫乐事是否在场都会加载，并且是**追加**到对方的标签上而不是替换它们。
- 为**每一种可食用的农夫乐事食物**补上生理数值——共 **80** 种。上面那些配方是纯数据层的，但一种食物**对身体做了什么**不可能是 JSON，因为它必须在进食钩子内部运行；所以这一半是本模组第一次与农夫乐事做代码层联动，并且被设计成：即使没装该模组，本模组依然照常启动、行为完全一致（见下）。
  - **钠**只来自**腌制的猪肉**：培根、熟培根、火腿、烟熏火腿（各 **+0.8**），培根三明治与培根煎蛋（**+1.2**），以及蜜汁火腿（**+2.0**）。刻意低于一勺盐的 3.0，因为一片培根咸，但并不是一勺盐——其余食物都不加钠，因为农夫乐事既没有盐这个物品，**它自己的配方里也完全没有用到盐**。
  - **维生素 C** 给植物，沿用本模组已有的尺度（苹果 12、胡萝卜 10、西瓜片 8）：番茄 **+10**、卷心菜 **+8**、番茄酱 **+8**、洋葱 **+6**、南瓜片 **+6**、卷心菜叶 **+4**——以及按用料比例给菜肴，因此璀璨沙拉 **+18**、水果沙拉 **+16**、普罗旺斯炖菜 **+16**，而只是拿一片番茄做点缀的三明治只有 **+4**。肉、蛋、面包、米饭、奶与巧克力一律为零：维生素在植物里，所以烤三文鱼无论怎么烤都不含维生素 C。
  - **碘**只给两种海带卷，即仅有的用 `dried_kelp` 做成的食物：一卷 **+0.30**——三片干海带（各 0.20）裹着一碗米饭，按「含海带的菜」计而不是按三片干海带计，因为米饭才是主体——切片则由砧板一刀出三片，是它的 **+0.10**。
  - **血糖**沿用模型已有的档位，并新增一档：拼装出来的一盘——炖菜、三明治、意面——是 **+0.6**，介于植物食物（0.4）与面包（0.7）之间，因为其中的肉与脂肪会拖慢淀粉。把每一顿熟食都按面包计会让它变成血糖尖峰。于是该模组的米饭与蜂蜜饼干取面包档，它的菜肴取新的混合菜档，肉排熟 **+0.5**、生 **+0.4**，蔬菜与沙拉 **+0.4**。
  - **饮品与风险。** 它的瓶装奶、三种甜饮（苹果酒、西瓜汁、热可可）与九种汤计入水量，正如原版奶桶与蘑菇煲那样；三种甜饮同时取甜饮档的血糖。它的生面团、生意面、鸡肉块与下界沙拉——即它自己打上 `c:foods/food_poisoning` 标签的四种——会触发细菌感染掷骰，每一种生肉排也会，因为农夫乐事的肉排就是生肉。
  - **没装它时依旧可完整游玩。** 依赖是 `compileOnly`：它把该模组放上编译器的 classpath，而**不**放进发布的 jar，因此发行版既不打包农夫乐事也不要求它，`fabric.mod.json` 也不写它。由于这些类在运行时并不存在，联动被拆成四个文件，保证模组其余部分触达的那个守卫完全不具名该模组：只有物品表与配方助手具名它的类型，而物品表仅写在静态初始化器里，JVM 只在该 object 首次被使用时才运行它。除非 `isModLoaded("farmersdelight")` 为真，否则没有任何代码触达它，因此本模组永远不会加载农夫乐事的类，也就不可能抛 `NoClassDefFoundError`。已通过把该依赖从开发运行环境中移除、再跑完整套自检验证：**243 通过、0 失败、无报错**。
  - 带上这份依赖还有第二个好处：把八十种物品写成 `ModItems` 字段名而不是注册名字符串，意味着**编译器**会逐一检查，因此农夫乐事某次更新若重命名了某个物品，构建就会失败，而不是悄悄从模型里掉一种食物。

### 变更
- **黄连素改为经 CYP3A4 代谢**，此前为固定速率。代谢速率以酶指标相对 85 基准缩放，因此在 85 时与模型原本的代谢完全一致，而在 10 时同样剂量需要 8.5 倍时间。这是模组中第一个「吃下某样东西会改变另一样东西持续时间」的相互作用：一份黄连在单独使用时约 9,400 tick 清除完毕，而体内充满葡萄柚时约需 17,800 tick。
- **`aliment:salt_water` 与 `aliment:crude_salt_water` 现在只接受真正的水瓶**，而不再是任意药水。此前两者都写作裸的 `minecraft:potion`，因此治疗药水或抗火药水搅进盐之后会变回盐水，把药水悄悄毁掉。现在它们与葡萄柚汁使用同一个 `fabric:components` 水过滤器。对任何曾把这些配方喂给非水药水的用法来说，这是**破坏性改动**——而这正是本次改动的目的。

### 修复
- **发酵罐在发酵完成后不能再补水。** 罐子存的是乙醇的**浓度**而不是总量，所以往还装着酒的罐里倒水桶会把它补满到三格，而酒精出罐时仍是满浓度：装一瓶、补满、再装三瓶，一份糖和酵母就能无限产出。现在只要乙醇大于零，水桶与水瓶都会被拒绝。发酵结束那一刻罐里有多少水，这一批就是多少；全部装瓶后乙醇清零，罐子才可以重新加水。空罐加水不受影响，普通的糖与小麦流程仍然依赖这一点。自测把这条刷法完整跑了一遍——装瓶、补水、再装瓶——断言一批料**恰好每格水出一瓶**；移除守卫后同一个循环会用 3 格水产出 8 瓶。
- **粗盐水炼药锅不会再被水炼药锅顶掉。** 它是唯一没有重写 `useItemOn` 的 Aliment 炼药锅，因此继承了 `AbstractCauldronBlock` 的实现，而那个分发器正是原版的 `EMPTY`——其中登记了空桶加水交互。于是倒一桶水会**把整个方块替换成满的水炼药锅**，把蒸发进度悄悄毁掉，岩浆桶也一样。现在粗盐水对任何物品都返回 `PASS`，这才是正确答案，因为本来就不该有物品用在它上面：浓度由 `stage` 属性承载而不是水位，多加的水无事可稀释。搅拌棒不受影响——`AlimentInteractions` 在原版介入之前就处理了它。另外三个炼药锅本来就重写了该方法，根本走不到那个分发器。
- **柳树树苗盆栽**现在会正确渲染为盆栽柳树。它的 blockstate 指向 `minecraft:block/potted_oak_sapling`，因此一直以来都被画成一盆**橡树**，而正确的 `aliment:block/potted_willow_sapling` 模型就摆在旁边却从未被引用。此问题是在添加葡萄柚对应文件时发现的——它是从同一个文件镜像而来的。
